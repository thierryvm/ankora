# PR — Next.js 16.4.3 → 16.4.6 (security patch)

@cc-ankora — 17 November 2026.

## Why

`npm audit --omit=dev` on `main` reported **GHSA-mfr8-8qww-v76h** (moderate): « Next.js: Information disclosure across root params when a 'use cache' function is called through unstable_cache() ». It affects `>=16.3.0 <=16.4.4`; the fix ships in 16.4.6, a patch release with no major change.

**Exposure in Ankora: none.** `git grep "unstable_cache\|use cache" -- src` finds nothing, and `next.config.ts` enables no cache-related experiment. The patch is taken anyway, as the global rule requires: a security patch that is available is taken right away and validated by the build.

## What

- `package.json`: `next` 16.4.3 → 16.4.6, still exact.
- `package-lock.json`: only Next's own packages move. Checked package by package against the previous lockfile:
  - `next` 16.4.3 → 16.4.6;
  - `@next/env` 16.4.3 → 16.4.6;
  - the eight `@next/swc-*` binaries 16.4.3 → 16.4.6 (darwin, linux gnu/musl, win32, arm64 and x64).
- `NOTICE`: regenerated by `npm run notice`, since `scripts/__tests__/generate-notice.test.ts` requires it to follow the lockfile.
- `eslint-config-next` stays at 16.2.6: out of scope, since the ESLint 10 upgrade is handled separately.
